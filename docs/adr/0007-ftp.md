# ADR 0007: Koneksi FTP/FTPS (browser file saja)

- Status: Diterima
- Tanggal: 2026-10-22
- Terkait: ADR 0001 (tech stack), `docs/SECURITY.md` bagian FTP/FTPS

## Konteks
TermUL hanya mendukung SFTP (di atas SSH) untuk browser file dan remote edit. Sebagian server, misalnya shared hosting
atau perangkat lama, hanya membuka FTP/FTPS tanpa akses SSH. Supaya file di server seperti itu bisa dikelola dari tempat
yang sama (panel file, transfer antar-server, edit dengan editor lokal), dibutuhkan klien FTP.

Keamanan credential adalah requirement utama. FTP biasa mengirim username, password, dan isi file tanpa enkripsi.

Opsi yang dipertimbangkan:

1. **Tidak mendukung FTP.** Paling aman, tetapi user tetap butuh aplikasi lain untuk server FTP.
2. **Hanya FTPS.** Tidak ada password plaintext, tetapi server lama yang hanya FTP tidak bisa dipakai.
3. **FTPS sebagai default, FTP biasa sebagai pilihan eksplisit dengan peringatan.**

## Keputusan
Opsi **3**, dengan Apache Commons Net (`commons-net`) sebagai klien.

1. `HostProfile.protocol` (`SSH` default, `FTPS`, `FTPS_IMPLICIT`, `FTP`). Profil lama tanpa field ini menjadi SSH. Untuk
   keluarga FTP, auth selalu password; key, jump host, auto-sudo, dan WSL diabaikan.
2. `RemoteFileService` menjadi interface dengan dua implementasi: `SftpFileService` (kode lama) dan `FtpFileService`.
   Panel file, transfer (`TreeTransfer`, salin antar-server), dan `RemoteEditSession` tidak perlu tahu protokolnya.
   `SftpLinks` memilih opener sesuai protokol profil.
3. Profil FTP selalu dibuka sebagai tab file saja (tanpa terminal). "Edit sebagai root" (sudo) hanya untuk SSH.
4. **FTPS**: sertifikat yang lolos validasi CA (truststore JDK) + hostname diterima. Kalau tidak lolos (mis. self-signed),
   TOFU dengan fingerprint `SHA256:` sertifikat leaf, disimpan di `ftps_known_certs` per host:port. Fingerprint tersimpan
   yang berbeda = **koneksi ditolak** (seperti host key SSH). Semua koneksi satu service (kanal data, koneksi transfer)
   wajib memakai sertifikat yang sama dengan koneksi kontrol pertama.
5. Kanal data FTPS memakai ulang sesi TLS kanal kontrol: socket data dibuka plain, dibungkus agar `getPort()` melapor
   port kontrol (cache sesi JDK berkunci host + port socket asli; argumen port `createSocket` diabaikan), lalu di-layer
   TLS. Tiap koneksi kontrol punya `SSLContext` sendiri agar tidak me-resume tiket koneksi lain (vsftpd: kunci tiket
   per proses). Tanpa ini, vsftpd (`require_ssl_reuse=YES`, default) menolak transfer dengan `522`.
6. Password dikirim sebagai `char[]`: perintah `PASS` ditulis langsung ke stream kontrol (`FtpClients`), tidak lewat
   API `login(String, String)` commons-net dan tidak lewat listener perintah (log).
7. Koneksi transfer terpisah dari koneksi kontrol (satu koneksi FTP hanya bisa satu perintah/transfer), jadi service
   menyimpan salinan password `char[]` selama koneksinya hidup untuk login ulang; di-zero saat service ditutup.
8. FTP biasa dikonfirmasi saat profil disimpan dan diberi peringatan merah di dialog profil.

## Konsekuensi
- (+) Server tanpa SSH bisa dikelola dari TermUL dengan panel, transfer, dan remote edit yang sama.
- (+) Sertifikat self-signed tetap terlindung dari MITM setelah TOFU, dan perubahan sertifikat ditolak keras.
- (−) FTP biasa tetap tidak aman; hanya dibatasi dengan peringatan. Password dan isi file bisa disadap di jaringan.
- (−) Dibanding SFTP, upload FTP tidak bisa memeriksa izin/owner sebelum menulis, mode file hanya dipertahankan kalau
  server mendukung `SITE CHMOD`, dan rename yang menimpa bergantung server (kalau ditolak: hapus lalu rename, tidak
  atomic). Deteksi konflik remote edit memakai `MLST`/`MDTM` (presisi detik); server tanpa keduanya hanya presisi menit.
- (−) Password ada di memori (`char[]`) selama tab FTP terbuka, bukan hanya saat login.
- (−) Satu dependensi baru (`commons-net`). Server test in-process (`ftpserver-core`) hanya scope test.
